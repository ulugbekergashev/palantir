# Кнопка «Facebook orqali ulash» (Targetolog) — настройка Meta-приложения

Клиника нажимает кнопку в панели (Targetolog → Kabinet). Дальше всё идёт само:

1. Открывается страница Hub с названием клиники, к которой подключается кабинет: так пересланную чужую ссылку легко заметить. Ссылка одноразовая. Дальше Facebook: человек входит и разрешает доступ.
2. Palantir Hub меняет код на 60-дневный токен. Секрет приложения хранится только в Hub, а сам токен лежит в очереди Hub не больше часа.
3. Токен через очередь Hub приходит в Palantir клиники.
4. Palantir находит рекламный кабинет, страницу и Instagram. Если кабинетов несколько, клиника выбирает нужный в панели.

ID и токены вручную вводить не нужно. Ручной способ (токен системного пользователя) остаётся в панели свёрнутым — для тех, кому нужен бессрочный токен.

## Что сделать один раз (владелец Palantir)

1. На developers.facebook.com/apps откройте приложение Palantir (то же, что для Instagram) или создайте новое (тип Business).
2. Добавьте два сценария (use cases):
   - **Create & manage ads with ads MCP server** — даёт разрешение `ads_mcp_management`. Без него Targetolog не получит инструменты Meta (MCP), останется только простой путь через план.
   - **Facebook Login for Business**.
3. Facebook Login for Business → Settings → **Valid OAuth Redirect URIs**: `https://<hub>/ads/callback`. Сейчас это `https://92-5-56-138.sslip.io/ads/callback`.
4. Settings → Basic: скопируйте **App ID** и **App Secret** и выполните:
   ```
   FB_APP_ID=… FB_APP_SECRET=… npm run hub:deploy
   ```
   Скрипт запомнит значения в `~/.palantir/hub.env`. Проверка: `https://<hub>/health` показывает `"ads":true`.
5. Если Facebook пишет «Invalid Scopes» или не спрашивает разрешения, приложению нужна конфигурация:
   - Facebook Login for Business → Configurations → Create, тип токена — **User access token**;
   - выберите разрешения: `ads_mcp_management`, `ads_management`, `ads_read`, `business_management`, `pages_show_list`, `pages_read_engagement`, `pages_manage_ads`, `instagram_basic`;
   - затем выполните `FB_LOGIN_CONFIG_ID=<id> npm run hub:deploy`.

## Ограничения

- **Пока приложение в режиме Development**, войти могут только люди с ролью в приложении (администраторы, разработчики, тестировщики). Вы сами можете пользоваться сразу. Для чужих клиник нужно:
  - пройти App Review: Advanced Access на `ads_management`, `ads_mcp_management`, `business_management`, `pages_*`;
  - пройти Business Verification.
- Токен действует **60 дней**. Продлить его без человека нельзя. За 5 дней до конца Palantir напишет владельцу клиники в Telegram. Повторное нажатие кнопки обновит токен, а тот же кабинет подключится сам.
- Деньги по-прежнему тратятся только по кнопке владельца клиники: включение, буст и изменение бюджета. Способ подключения на это не влияет.

Проверка без настоящего Facebook: `npm run test:ads-hub`.

## Без своего Meta-приложения: Pipeboard

Если Meta-приложение создать нельзя (например, Meta закрыла аккаунту раздел для разработчиков), кабинет можно подключить через Pipeboard. Pipeboard — Meta Business Partner с уже одобренным приложением и своим MCP-сервером (`https://meta-ads.mcp.pipeboard.co/`).

1. Клиника заходит на pipeboard.co через «Войти через Facebook» (обычный вход, аккаунт разработчика не нужен) и подключает там рекламный кабинет и страницу.
2. На pipeboard.co/api-tokens создаёт токен.
3. Вставляет токен в панели: Targetolog → Kabinet → «Pipeboard orqali ulash».

Дальше Palantir проверяет токен и сам находит кабинет и страницу. Если кабинетов несколько, клиника выбирает в панели.

Как это устроено внутри:
- Токен Meta к Palantir не попадает. Палантир работает только через инструменты Pipeboard: и модель, и денежная охрана (лимиты, наблюдение, остановка — `server/ads/backend.ts`).
- Правила те же, что для MCP самой Meta (`server/ads/mcpRules.ts`):
  - чтение разрешено (`get_*`, `search_*`);
  - создавать можно только на паузе;
  - паузу модель ставит сама;
  - `ACTIVE`, бюджет, ставка и `create_budget_schedule` идут карточкой владельцу;
  - копирование, отчёты и неизвестные инструменты закрыты.
- После паузы через Pipeboard статус перечитывается. Если кампания не остановилась, владелец получает сообщение «срочно остановите в Ads Manager».
- Если Pipeboard не отдал расход, он считается неизвестным, а не нулём. В этом случае ничего не включается.
- Готовые планы (`ads_plan`) и загрузка видео работают только с токеном Facebook. Через Pipeboard кампании строит сам Targetolog.

Минусы:
- Pipeboard — третья сторона с доступом к кабинету.
- У бесплатного тарифа есть лимиты.
- С настоящим Pipeboard ещё не проверено. Названия и ответы инструментов взяты из их открытого кода (2026-11-21), у хостинга их может быть больше: всё неизвестное закрыто.

Проверка без сети: `npm run test:ads-pipeboard`.

## Без приложения и без Pipeboard: коннектор claude.ai (рекомендуется)

Meta сама пускает claude.ai к своему MCP-серверу (`https://mcp.facebook.com/ads`) без своего приложения. Palantir работает на подписке Claude того же компьютера через Agent SDK, а SDK подгружает коннекторы claude.ai этой подписки. Значит, Targetolog может работать через коннектор владельца:

1. claude.ai → Settings → Connectors → **Add custom connector**: имя `Meta Ads`, адрес `https://mcp.facebook.com/ads` → Connect. В окне Facebook отметить кабинет и страницу. Это обычный вход, не раздел разработчиков.
2. Панель Palantir: Targetolog → Kabinet → **«Claude orqali ulash»**. Palantir сам находит коннектор (по адресу, только `source: claudeai`), кабинеты и страницы. Если кабинетов несколько, владелец выбирает в панели.

Аккаунт claude.ai коннектора должен совпадать с подпиской, под которой работает Palantir на этом компьютере. Токен в Palantir не хранится.

Как устроено (`server/ads/claudeai.ts`):
- **Модель.** В разговоре Targetolog'а коннектор включается. Видны только сам Meta-коннектор и только инструменты, которые не закрыты правилами (≈51 из 117). Остальные коннекторы владельца (Gmail, Drive…) скрыты через `disallowedTools`. Каждый вызов проходит тот же PreToolUse-guard и те же правила Meta (`mcpRules.ts`).
- **Денежная охрана.** Сам сервер Palantir к коннектору подключиться не может. Расход, статус, пауза и подтверждённое владельцем действие выполняет «исполнитель»: короткая сессия SDK (модель `ADS_RUNNER_MODEL`, по умолчанию haiku). Ей видны только нужные инструменты, и она вызывает их ровно с заданными аргументами. PreToolUse отклоняет любой другой вызов. Ответ записывает PostToolUse, а не модель. Один вызов занимает ~13 с и ~11 тыс. токенов.
- **Наблюдение** за кампаниями идёт раз в 30 минут, а не в 10 (`CLAUDEAI_WATCH_MS`): каждое чтение — запрос к подписке. Дневной бюджет Meta держит сама.
- **Пауза.** После паузы статус перечитывается. Если не остановилась — сообщение «срочно остановите». Если расход не прочитан — «неизвестно», ничего не включается.
- **Форматы.** Аргументы и ответы Meta проверены на настоящем кабинете (2026-11-22, только чтение):
  - `ads_get_ad_entities {ad_account_id, level, fields, object_ids | filtering, date_preset}` → `{"ad_entities": "<JSON>"}`, суммы `{value, unit}` в основной единице;
  - `ads_update_entity {entity_id, entity_type, fields: "<JSON>"}`, бюджет в центах.
- **Что не работает.** Готовые планы (`ads_plan`) и загрузка картинок/видео из Palantir работают только с токеном Facebook. Через коннектор Targetolog использует картинки, уже лежащие в кабинете.

Проверка: `npm run test:ads-claudeai` (без сети). Живое чтение: `npx tsx scripts/live-claudeai-probe.ts <ad_account_id> <page_id> <campaign_id>` — только чтение.
